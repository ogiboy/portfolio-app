# Feature Workflow

1. Read `AGENTS.md`, the owner map, applicable decisions, and the relevant roadmap/plan.
2. Confirm worktree, branch, commit, and unrelated dirty state before editing.
3. State the source owner, public behavior, non-goals, and TDD Route. For this project the default route is `Mode: off`, `Decision: skipped`, with proportional tests and verification.
4. Make the smallest source change in the canonical owner; keep browser behavior in client leaves and route handlers thin and read-only. For visual work, state the alive-interface job and prove normal-motion, reduced-motion, mobile, and critical-render boundaries proportionally.
5. Run targeted checks, then record commands, date, commit, result, artifacts, and blockers in the evidence bundle.
6. Update the checkpoint if work remains, hosted state changed, or drift was found.

Approved sequence IDs and future order live in the current roadmap; progress and next action live only in `.ai/checkpoints/portfolio-overhaul.md`. The public DNS-AID index entrypoint is the only accepted DNS discovery record. OAuth, `auth.md`, and an MCP server card remain absent until real prerequisites exist and a later decision changes the boundary.
