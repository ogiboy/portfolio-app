# Roadmap: Search, AI Discovery, Brand, and Observability

## Status

Current expansion of the portfolio overhaul after `AR-2`. The active execution state remains in `.ai/checkpoints/portfolio-overhaul.md`.

## Outcome

Make H.O.T. discoverable as Halil Oğuzcan Toptaş's developer and homelab portfolio through truthful localized content, technically correct indexing signals, accessible social previews, source-backed agent discovery, and privacy-first measurement.

2. `SEO-2`: centralize localized titles, descriptions, canonical URLs, reciprocal EN/TR alternates, robots directives, and optional Google verification metadata.

6. `SEO-5`: add focused unit and browser coverage for metadata owners, canonical/hreflang output, structured-data safety, H.O.T. identity, privacy controls, and indexable routes.
7. `SEO-6`: run full local gates, desktop/mobile EN/TR browser QA, social/metadata inspection, structured-data validation, preview verification, hosted checks, review, merge, and production verification as separate evidence classes.

9. `SEO-8`: verify the domain in Google Search Console, submit the canonical sitemap, inspect representative EN/TR URLs, and monitor Page Indexing, Search Performance, Core Web Vitals, and generative-AI discovery reports.

## Content Strategy

- Lead with the full identity and the H.O.T. mark, not generic “frontend developer” keyword repetition.
- Keep client work, independent software, homelab operations, automation, and browser experiments as distinct proof categories.
- Prefer first-hand implementation notes, failure analysis, benchmarks, diagrams, and verified outcomes over broad tutorial summaries.
- Keep project records shared-source until a dedicated localization pass; never claim complete EN/TR project-content parity.
- Add dates only where they reflect a real publish or human-edited update and can be maintained.

## Search and Agent Boundaries

- Search metadata improves eligibility and understanding; it does not guarantee crawl, index, rank, rich results, AI citations, or traffic.
- Existing Markdown negotiation, Agent Skills, WebMCP, API catalog, OpenAPI, health, robots, and sitemap surfaces remain source-backed and read-only.
- `llms.txt`, OAuth discovery, protected-resource metadata, `auth.md`, MCP Server Card, and DNS-AID remain absent unless a supported consumer or real service prerequisite exists.
- Search Console, DNS verification, provider settings, deploys, and recrawl requests are external state and require independent evidence.

## Verification Contract

- Focused checks during each implementation slice.
- Full `package.json` gates before push.
- Rendered HTML checks for unique localized title, description, canonical, hreflang, robots, OG/Twitter, and JSON-LD output.
- Real browser checks for H.O.T. identity, privacy opt-out, EN/TR routes, mobile layout, reduced motion, project detail, and WASM isolation.
- Post-deploy Rich Results Test and Search Console evidence are follow-up provider evidence, not inferred from local tests.

## TDD Route

Mode: off. Decision: skipped. Test posture: proportional unit, route, browser, build, and provider verification. No strict RED/GREEN cycle is implied.
